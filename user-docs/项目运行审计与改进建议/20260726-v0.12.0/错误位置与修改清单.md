## 三、原材料中的错误判断或不安全方案

| 原说法 | 核对结论 | 正确处理 |
| --- | --- | --- |
| Resume 从头执行且不保留计划/节点 | 判断不成立 | 保留已有 checkpoint、计划、工具证据；只修复真正缺口 |
| Runtime 应再做网络重试和退避 | 会与 `DeepSeekClient` 重复 | Provider 层唯一负责网络重试，Runtime 只做协议恢复与预算门 |
| 网络失败自动切备用 Provider | 违反 DeepSeek-only | 不实现 |
| 每 N 轮保存比逐工具 checkpoint 更合适 | 会扩大未持久化窗口 | 保留逐请求预留与逐批次原子 checkpoint |
| 直接复制参考仓库解决方案 | 参考仓库无复制许可且技术栈不同 | 仅参考可观察行为，不复制专有实现 |
| 分块部分写入大文件 | 会破坏原子快照/undo | 先设计事务式 staged merge，再考虑独立能力 |
| 默认开启 LLM 反思、记忆抽取、A/B 自动调参 | 增加成本、隐私面和不可复现性 | 默认关闭；只做观察性历史，显式开启另议 |
