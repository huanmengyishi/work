# 后续版本建议

日期：2026-07-26

原则：先完成一个可验证、可回滚、不会无限消耗的 v0.12.0，再推进架构性扩展。参考项目只用于核对行为边界，不复制无许可证源码，也不改变 DeepSeek-only 约束。

## 一、v0.12.0 本轮完成与发布闭环

以下第 1 至第 7 项已完成并通过 502 项全量回归；第 8 项采用现有 editable 环境加隔离 XDG 实例冒烟，在线认证因用户 API 余额耗尽延期；第 9 项由最终 Git 发布步骤完成。

1. 把 `ArtifactVerifier` 接入 Runtime 的真实受管证据链，尤其是 Word 的 `render -> file_apply -> document.parse` 元数据；不得绕过 Tool Manager 直接读取任意路径。
2. 让 Session Deliverables 复用 apply/delete/undo active lineage，保证创建后删除不算完成、撤销删除后才恢复。
3. 补齐 Memory 容量、反馈参数和 PerformanceHistory 上限的显式默认配置；迁移只增加缺失键，不覆盖用户值。
4. 为 shell 特殊字符、POSIX/Windows 文件锁、Health 依赖注入、YOLO 配置入口和依赖清单增加/完成聚焦测试。
5. 运行一次全量离线验证；真实 PTY 行为由全量测试中的 PTY 回归覆盖。
6. 将 `pyproject.toml`、`agent/__init__.py` 升级到 `0.12.0`，同步 schema 7、接口契约 3 和配置默认值文档。
7. 新增 `docs/releases/v0.12.0.md`，更新源码 README、用户 README、工作日志及版本化 Word。
8. 完成 `agent --version`、`--help`、隔离 `agent init`、缺 Key 前置失败、launcher 和 `pip check` 冒烟；wheel/sdist 干净安装保留为后续发布增强门。
9. 提交、创建注解 tag `v0.12.0`、推送 `main` 和 tag；核验远端引用及 GitHub Actions。

## 二、v0.12.1：闭环预算和验证修补

- 将每 turn 预算扩展为可选 Session 生命周期预算，并明确 Resume 是继承剩余额度还是需要用户显式追加。
- 预算状态增加单调性、revision 和停止原因测试，防止新 turn 意外清零被误写成“总任务预算”。
- 扩展 Artifact 完成门到 Markdown/JSON/YAML/Python，同时保持内容、路径、大小和数量上限。
- 为受管测试结果建立结构化摘要，但不把字符串中出现 `passed` 当成通过证据。
- 在验收 runner 记录版本、`git_head`、dirty 状态、Python/依赖、脱敏配置 schema 和 fixture 哈希。

## 三、v0.12.x：Document Agent Pipeline

先设计再实现，不直接加入材料中的递归伪代码：

1. `DocumentPlan`：明确输入清单、章节树、来源映射、每章预算和最终目标文件。
2. 章节生成：每章独立临时 Artifact、独立校验、确定性顺序和幂等 ID。
3. 事务式合并：所有章节通过后一次受管 apply；失败时保留中间证据但不产生半完成最终文件。
4. 质量门：DOCX OPC/XML/CRC/Zip Bomb、正文非空、章节存在、来源覆盖、无截断。
5. Resume：只重做未生成或验证失败的章节，不重复已验证章节。

不要直接实现“对一个大文件分块部分写入”；它会破坏快照与 undo。若确有需要，应先设计 staged file + 最终原子替换 + 完整回滚协议。

## 四、v0.13.0：Memory 2.0 的安全增量

- CLI 增加带数量/字符上限的 export、详情和高级筛选；import 必须预览、去重、schema 校验和显式确认。
- 给容量维护结果增加原因统计，让用户看见哪些记录会被淘汰。
- 基于显式用户反馈更新置信度，不按“使用次数多”自动认定正确。
- LLM 记忆抽取保持默认关闭，纳入统一请求/Token预算，输出经过 schema、长度和脱敏检查。
- 跨项目知识继续使用显式 global scope；不得自动把私有项目内容升级为全局知识。

## 五、v0.14.0：Evidence Engine

- 定义有版本的 `EvidenceRule` 接口和少量确定性规则，不一开始做开放式插件市场。
- 文档：文件存在、结构可打开、正文非空、章节/来源覆盖、大小和截断。
- 代码：语法、静态检查、编译、测试和构建；保留命令、退出码与有界输出摘要。
- 服务：只通过受管 HTTP/进程工具验证状态，不允许 Runtime 直接访问系统。
- 完成状态只能由真实 ToolResult 和规则结果驱动，模型文字不能单独把任务改成成功。

## 六、v0.15.0：Durable Intent Journal

这是实现外部副作用可恢复性的前提，应独立设计：

- mutation 前记录 intent，后记录 result；用 request ID、参数摘要、目标哈希和 revision 对账。
- Session revision/CAS 处理并发 Resume；冲突时拒绝并给出明确恢复路径。
- 对本地文件可提供 exactly-once-like 的受管语义；对外部系统只能记录和人工核验，不能夸大保证。
- 中断、进程崩溃、系统重启测试必须覆盖“副作用完成但结果尚未 checkpoint”的窗口。

## 七、工程债务，单独重构

`runtime.py`、`convergence.py`、`tools/manager.py` 的职责过载是真实问题，但不应与功能发布混在同一提交。建议每次只抽取一个纯模块：

1. 先锁定接口与 characterization tests。
2. 提取无副作用计算，例如 completion gate 或 context budget。
3. 保持公开签名和事件顺序不变。
4. 全量通过后再提取下一个模块。

## 八、明确不做

- 不增加备用 Provider；DeepSeek 仍是唯一推理模型。
- 不从无许可证的参考仓库直接复制实现。
- 不在 Runtime 再叠加网络重试。
- 不默认开启重型 Vector、LLM Reflection、LLM Memory Extraction 或 A/B 分流。
- 不在缺少隔离/合并协议时启用并行写步骤或子 Agent。
- 不为追求“全部建议已实现”而引入没有测试和回滚路径的代码。
