## 三、决定能否启动的关键链路

```text
CLI 参数与环境
  -> API Key 无泄密预检
  -> 配置只补默认值
  -> Project / Memory / Vector 按需初始化
  -> Runtime 建立 AgentState 与预算
  -> DeepSeek 请求
  -> ToolRequest -> PermissionManager -> ToolResult
  -> checkpoint / Session 终态
  -> CLI 按 completed / incomplete / exception 返回退出码
```

当前修改直接覆盖了此前最影响实例运行的三个问题：

1. 无 Key 失败路径不应先下载 Vector 模型。
2. Session 未完成不能向 shell/CI 返回成功码 0。
3. 长任务不能在请求、Token 或时间无总门限的情况下继续消耗。

这三点已由全量测试和隔离实例冒烟验证。

## 四、当前可合理声明的能力

- DeepSeek 是唯一 Provider；没有引入备用模型。
- 写入继续遵循受管 diff/apply/undo 与 Permission Manager。
- 新安装 Vector 默认关闭；显式开启也采用惰性加载。
- 每 turn 有模型请求、Token 和时间预算；预算耗尽保存可 Resume 状态。
- CLI 设计为 0=完成、2=未完成可恢复、1=异常。
- 计划步骤具有类型、父节点、轮次估算、Artifact、验证规则和进度权重。
- 进度百分比只来自已满足步骤，不猜测 ETA。
- Artifact verifier 可离线检查文本、JSON、YAML、Python 和 DOCX 结构安全。
- Memory 新写入类型受限，容量维护默认 dry-run，Correction/Decision 受保护，反馈幂等。
- 性能历史只保存安全标量，不自动调整策略。
